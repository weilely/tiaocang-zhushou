# 调仓助手（Dart 包名 invest_tracker）

一个用 Flutter 写的安卓投资记账 App：记录基金 / 股票持仓，自动抓取行情，统计收益，并在仓位偏离目标时提醒调仓。

- 应用显示名（桌面图标 / 任务栏）：**调仓助手**（`AndroidManifest.xml` 的 `android:label`、`MaterialApp.title`）
- Dart 包名仍是 `invest_tracker`（改包名要动所有 import，不值当）

数据全部保存在手机本地 SQLite，不上传任何服务器。

---

## 功能

底部导航五项：**首页 / 持仓 / 调仓 / 关注 / 设置**。

| 模块 | 说明 |
| --- | --- |
| **首页** | 标题栏：账户下拉 + **上证**（两个字的标签 + 价格与涨幅；60 秒自动刷新，仅前台运行时拉取）；跑马灯只滚动**其余**指数（上证固定在标题栏，所以从跑马灯里去掉）。右侧只剩 **⟳ 刷新行情** 一枚图标。卡片：总市值（持仓市值 + 现金余额）、**当日收益**、持仓收益、**实现收益**、累计收益及各自收益率；持仓分布环形图（图例**只显示占比、按占比升序、不显示金额**，圆环与图例共用同一份顺序所以颜色对得上；已删掉重复的「主要持仓」卡片 —— 进标的详情走「持仓」页签）；最底部是**收益统计卡片**。**「调仓监控」卡片已删除**：它按旧的「资产大类」目标算，目标改成按具体标的之后那张卡已经失效，调仓口径统一在「调仓」页 |
| **持仓** | 每只标的一张卡片：名称/代码、市值（配色跟随累计收益正负）/占比、当日收益、持仓收益、累计收益、份额/成本，以及分隔线下的「净值（涨跌幅）」与净值日期；顶部三枚按钮（拍照导入 / 添加基金 / 定投管理）与排序行（持仓市值·收益率·当日收益·持仓成本 ⇄ 升序/降序）。**「记一笔」悬浮按钮与标题栏 ＋ 图标都已去掉**：新增标的走「添加基金」（期初持仓导入，不联动现金），已持有标的在**标的详情页**顶部买入 / 卖出 / 定投 / 分红 |
| **调仓** | 目标是**具体的基金 / 股票**（在「设置 → 调仓目标」里填每只标的的目标占比）。顶部是调仓总金额（= 调仓基金市值 + 追加调仓金额）、**页内滑杆调节的触发阈值**（不再弹窗）；**「重新计算」按钮已去掉**，改成下拉刷新（首次进入仍自动补关联 ETF + 刷行情）。每只标的一张卡片：**当天净值已公布就不写「预估」**（显示 `市值 / 净值 / 当日涨幅`，涨幅取库里那条净值的真实 `change_pct`、只读不可改），没公布才显示 `预估 / 预估净值 / 当日预估涨幅`（可手改）；再加目标市值、调仓份额、关联 ETF，以及「需追加买入 / 需减仓卖出」多少与偏离多少。底部占比条上有一条**目标刻度线**（位置 = 目标市值 ÷ Σ预估市值，与当前占比同一分母）。输入框与告警底色都跟主题走，深色主题下数字照样看得见 |
| **关注** | 搜索添加关注标的；表头固定「代码名称 / 净值」，收益列左右滑动，点表头按 近1周 / 近1月 / 近6月 / 近1年 / 近3年 / 近5年 / 成立以来 排序（第三次点击取消排序）；长按拖动排序或置顶。行高从 58dp 收紧到 **48dp**，一屏能多看几只 |
| **设置** | 多账户管理、**调仓目标**（只列**当前还有份额**的标的）、**数据维护中心**（全部交易 / 历史净值与重建 / 基础数据库 / 备份恢复 / CSV 导入导出）、**行情指标**、**关于**。四张卡片（账户管理、调仓目标、数据维护中心、行情指标）**都能折叠**；「关于」卡上只留一行「调仓助手 v1.0.0　吹角天明@MLB」，数据说明/免责声明点一下弹窗看 |

**「行情指标」**（原「大盘行情」）：跑马灯显示哪些指标。可以按代码添加**指数 / ETF / 股票**——
填代码（指数写 `sh000300` 这样带前缀的，ETF 和股票直接写 6 位，会自动补 `sh`/`sz`/`bj`）→ 先查本地基金库、
再联网（东财 push2，UTF-8 JSON）拿名称与最新价 → 自己定一个**跑马灯简称** → 进入**待选**；
待选里点一下加入跑马灯、再点一下移回待选，右侧 × 删除。行情每分钟自动刷新（首页 + 前台时）。
行情源按代码分流：指数走新浪精简行情，ETF / 股票走东财 push2（两路互不影响，一路挂了另一路照常显示）。
| 现金 | 不在导航里，从首页「现金余额 → 管理」进入。现金余额实际是货币基金 / 国债逆回购：充值 / 提现 / 调整 / 收益四个入口，按本金 × 年化 × 天数 ÷ 365 快填收益；当月收益、累计收益只在管理页显示 |

**趋势图的浮窗默认常显**：进页面就有一条浮动提示落在**最后一个点**上，拖动跟手、松手不消失，换区间后重新贴到末日。
**「参考收益率」那一格显示的是按当前区间折算后的值**（自定义年化基准 = 年化 × 天数 ÷ 365），与图例、图上虚线端点同源；
年化原值在点开的面板里填，面板上还会写一句「当前区间（近1月）折算为 0.25%」，两个数字不会对不上。

**拍照导入（OCR）为什么以前会闪退**：`google_mlkit_text_recognition` 插件只把**拉丁文模型** `implementation` 进包，
中文模型 `text-recognition-chinese` 是 `compileOnly`（只编译期可见）。代码用 `TextRecognitionScript.chinese` 时，
release 包里只有 `Latn` 模型、没有中文模型，底层原生库直接失败 → **选完图 App 退出**。
修法是在 `android/app/build.gradle.kts` 里显式加 `implementation("com.google.mlkit:text-recognition-chinese:16.0.1")`
把中文模型打进包（离线可用、不依赖 Google 服务）。验证方式：拆 APK 看 `assets/mlkit-google-ocr-models/.../Hani_ctc/...`
是否存在，以及运行时 logcat 里 `DynamiteModule: Selected local version of …text.chinese` + `Loading … Hani_ctc/…`。
同时 `OcrSource.recognize` 改成返回 `OcrResult`（带 `error`）而不是往外抛，识别失败只提示「可改用手工录入」。

**刷新不再弹「刷新失败：Null check operator used on a null value」**：改名循环以前遍历
`[...trackedAssets, ...linkAssets]`，而关联 ETF 是为估算临时合成的、没有 id，`a.id!` 直接抛异常。
现在收成纯函数 `logic/quote_sync.dart` 的 `assetRenames()`：只处理库里有 id 的标的。

**图标**：换图后跑 `tool/make_icons.ps1`（PowerShell + System.Drawing）重新生成 —— 它采样四角底色写回
`values/ic_launcher_background.xml`，按容差取内容包围盒，然后出 legacy（内容宽 = 画布 77%）与自适应前景
（内容宽 = 画布 60%，落在 66dp 安全圈内）两套 PNG。脚本含中文，必须存成 **UTF-8 带 BOM**，否则 Windows PowerShell 5.1 会按 GBK 解析报错。

**「当日收益」是个固定叫法**：不再按行情日期改名（以前行情是今天就写「今日收益」、否则写「前日收益 09-11」），
也不带日期 —— 同一块界面在不同日子换字容易被当成两套口径。数值口径没变（仍取最近一个交易日的涨跌），
要看是哪一天就看总览顶部的「市值更新日期」。

**标的详情页以交易记录为主**：顶部只留 8 个格子的「持仓概览」（份额/成本、最新价/市值、当日/持仓收益、累计/实现收益），
下面是交易记录 —— 按月折叠（默认展开最近一个月），**不显示年份、不做缩进、记录之间不留间隔**。

**「全部交易」按基金 / 股票分组**，每组显示笔数与买/卖合计；右上角「批量删除」进多选，
可整组勾选或全选，删除会连带清掉这些交易联动生成的现金流水（与单笔删除同一个入口）。

日常操作：**首页标题栏 ＋ / 持仓 → 标的详情页 → 顶部交易按钮**记一笔，买入/卖出/分红会**自动记入现金账户**，不需要额外勾选。

### 记一笔表单：按交易日期查净值

买入 / 卖出 / 分红共用同一个表单，三件事是自动的：

1. **净值按「交易日期」查**，不用手填。改日期就重新查一次，日期下面那行提示会写明净值到底属于哪一天。
2. **主字段随交易类型互换**：买入是「花多少钱 → 得多少份额」，所以金额在前、份额自动算；
   卖出是「卖多少份额 → 得多少钱」，所以份额在前、金额自动算。派生字段仍可手改，手改后就不再自动覆盖。
   份额口径与定投一致（`roundDcaShares`：场外基金 2 位小数、股票/ETF 取整），金额落到分。
3. 分红只填到账金额。

取净值的顺序（`logic/nav_lookup.dart`，逐条有单测）：

| 序 | 来源 | 条件 |
| --- | --- | --- |
| 0 | 当日行情 | **场内标的**（ETF / 股票）：当天**市价**优先于同日基金净值。场内是按市价成交的，净值只是会计口径（实测 510300：净值 4.5489 vs 收盘 4.5520）；且行情日期必须**正好是所选日期**，否则宁可要那天的净值 |
| 1 | 本地 `nav_history` | 所选日期**精确命中**（查前后各 20 天窗口，命中就不联网） |
| 2 | 当日行情 | 所选日期就是今天、且内存里有行情（场外基金的 `est` 标成「盘中估值」） |
| 3 | 联网 | 精确命中 |
| 4 | 联网 | **顺延**到所选日期之后、不晚于今天的第一个有值日 |
| 5 | 联网 | 回到所选日期之前最近的一个有值日 |
| 6 | 本地兜底 | 同 4 / 5，只用本地窗口（离线也能填上） |

**顺延优先于回退**：非交易日下单本来就在下一个交易日成交，用下单日之前的净值成交是错的。
这套规则与定投的 `resolveDcaPrice()` 是同一口径，一个 App 里不摆两套取价逻辑。
只有在「今天还没出净值」时才会回退到上一个交易日（提示行会写明日期，用户可按需改）。

**场内与场外分开**：ETF / 股票按**市价**成交，所以当天有市价就填市价（与标的详情页的
「最新价」一致）；场外基金没有市价，已公布的净值优先于盘中估值。两者都不猜：行情日期
对不上所选日期时就退回到那一天的净值。

提示行始终写明净值**实际属于哪一天**，所以「该日无净值，取 09-14 净值 1.7548」这类字样
是刻意显示的，不是错误。

> 查询是**只读**的：查到的净值不会写进 `nav_history`，否则用户随手翻几下日期就会往历史表里塞零散的点。
> 历史净值的沉淀仍然只由「设置 → 数据维护中心 → 更新历史净值」负责。


### 现金与交易的联动

买入扣款、卖出入账、分红入账会按交易日期自动写一条现金流水（`cash_txns.src_txn_id` 指回原交易）。
编辑或删除交易时，联动流水会一并更新 / 删除，不会重复记账。

**所有产生交易的路径都联动**，包括容易漏掉的两条：

| 来源 | 是否联动 |
| --- | --- |
| 手工录入 / 编辑交易 | ✅ |
| **定投自动补记**（`runDueDca` 按期补的那些） | ✅ |
| **CSV 导入** | ✅ |
| 拍照导入的**期初持仓** | ❌ 刻意不联动——那笔钱在建账之前就花掉了 |

实现上收敛到一个入口 `AppState.saveTxnAndLinkedCash()`（符号规则在
`linkedCashTxnFor()`，与 `Txn.netCash` 完全一致），全仓除期初持仓外**不再有**
直接 `db.saveTxn` 的地方；删交易时 `deleteCashBySrcTxn` 与 `deleteTxn` 成对出现，
不会留下孤儿流水。这三条都有测试与结构性检查兜着。

**联动流水不能在现金页删除**：它是那笔交易的影子，单独删掉会让余额与交易对不上。
现金页给这类流水加了 `自动` 标，并写明「随交易自动记，请到交易记录里删」；
实现上 `CashTxnTile` 在联动情况下**根本不构造** `Dismissible`，所以是结构上的不可删，
而不是「构造了再判断」。

口径：`现金余额 = Σ cash_txns.amount`，`总市值 = 持仓市值 + 现金余额`。
现金的**当月收益 / 累计收益**只记不摊薄成本，只在现金管理页展示。

> 联动是常开的，所以**回补历史流水会让现金变负**（买了却没记过充值）。想修的话先记一笔「充值」。
> 早于联动功能存在的历史交易**不会自动补记**；这类数据在收益统计的「资金流」页会有
> 「现金流水不完整」的提示与差额说明。

### 调仓方案（按具体标的）

设计稿 `pic/111.jpg`。目标是**具体的基金 / 股票**，不再是资产大类：在
「设置 → 调仓目标」里给每只持仓标的填目标占比（留空的按「保持现状」处理，不参与买卖建议），
调仓页负责把比例翻译成金额与份额。

卡片上的数字口径（`logic/rebalance_plan.dart`，用设计稿的样例逐条验算过）：

```text
调仓总金额 = Σ预估 + 追加调仓金额        329231.57 = 319231.57 + 10000
预估       = 份额 × 预估净值              31043.31 = 17601.9 × 1.7637
目标       = 目标占比 × 调仓总金额        32923.16 = 10% × 329231.57
差额       = 目标 − 预估                  1879.85
调仓份额   = 差额 ÷ 预估净值              1065.86
偏离       = 差额 ÷ 预估                  6.06%   （超阈值就出顶上那条告警）
进度条     = 该标的预估市值 ÷ Σ预估市值
```

「偏离」是**相对量**而不是占比的百分点之差：5% 的阈值配的就是它。追加的那笔钱按目标比例
分下去，所以「追加调仓金额」填进去之后，每只标的的目标市值都会跟着抬高。

**当日预估涨幅**（决定「预估净值」，也就是当天到底按什么价算）：

| 标的 | 涨幅来源 |
| --- | --- |
| ETF / 股票 | **实时涨幅**，预估净值就是实时价（与标的详情页「最新价」一致） |
| 场外基金 | **关联 ETF 的实时涨幅直接填入**：预估净值 = 最新已公布净值 × (1 + 涨幅) |
| 场外基金（今日净值已公布） | 0 —— 当天已经结束，再叠一层估计就把涨幅算两遍了 |

折算比例留了个常量 `kFundEstimateFactor`（现在是 1.0 = 直接取）。若哪天想按「联接基金
约 95% 仓位」折算，把它改成 0.95 就行。

场外基金没有实时行情（实测 021362、025497 的估值字段都是空的），所以要靠关联 ETF。
关联关系**自动猜**：按名字在公司名优先、其次名称重合度（`logic/link_etf.dart`），
「易方达国证价值100ETF联接发起式A」会配到「价值ETF易方达 159263」，
「易方达黄金股指数发起式A」配到「黄金股ETF永赢 517520」。猜错不要紧 ——
卡片上写着用的是哪只、点右边就能改，也可以「清除关联」。

「当日预估涨幅」在卡片上可以直接改（改完预估净值、差额、份额、偏离全部跟着变），
点「重新计算」则清掉手改、按最新行情重新估一遍。

## 收益口径
页面上共四种收益，口径互不相同，看懂这四个就不会被数字绕晕：

| 指标 | 定义 | 卖出后会变吗 |
| --- | --- | --- |
| **今日收益 / 前日收益** | 最近一个交易日的涨跌盈亏 = `(现价 − 昨收) × 份额` | 变（份额少了），但**当天没行情时自动退化为上一交易日的收益** |
| **持仓收益** | 浮动盈亏 = 市值 − 持仓成本 | 金额变（随份额），**收益率不变** |
| **已实现收益** | 卖出价差 + 历史分红 | 只增 |
| **累计收益** | 建仓以来全部收益 = 持仓收益 + 已实现收益 | 按市价卖出时**不变**；卖出价偏离市价才变 |
| **年化收益率 XIRR** | 按现金流加权，二分法求解 | 每次买卖都会重算 |

### 今日收益 / 前日收益

`Quote.infoDate` 记录该报价所属的交易日：

- 场外基金取 `PDATE`（净值日期），盘中估值取 `GZTIME`
- 股票 / ETF 取东财 `f297`（形如 `20260911`）；逐只兜底时改用 `f86`（行情最后更新时刻的秒级时间戳），
  因为 `f297` 对个股返回的是**报告期**（如 `20260630`）、对 ETF 直接返回 `-`

行情日期 == 今天 → 显示「今日收益」；否则显示「**前日收益 09-11**」这样的带日期标签；
拿不到日期信息时退回中性的「当日收益」。

所以周末、节假日、开盘前打开 App，看到的都是**上一个交易日**的收益，并于标签上写明日期，
不会再出现「周一早上显示『今日收益』其实是上周五」这种误导。

### 成本核算：移动加权平均（平均成本法）

```
买入：成本 += 成交金额 + 手续费          份额 += 买入份额
卖出：成本 −= 成本单价 × 卖出份额        份额 −= 卖出份额
      已实现收益 += 卖出净额 − 成本单价 × 卖出份额
```

因为卖出用的是**卖出前**的成本单价，所以

```
卖出后成本单价 = (成本 − 单价×卖出份额) / (份额 − 卖出份额) ≡ 成本 / 份额
```

**部分卖出后成本单价严格不变**，而 `持仓收益率 = 现价 / 成本单价 − 1`，因此**持仓收益率也不变**。
分红只进「已实现收益」，同样不摊薄成本，不影响持仓收益率。

这些不变量都有回归测试保护（`test/core_test.dart` 的「平均成本法不变量」组）。

历史净值存在 `nav_history` 表（代码 / 净值日期 / 净值 / 累计净值 / 涨幅 / 是否分红）。
联网更新是**增量的**：库里没有就全量拉（`pingzhongdata` 一次请求即可），
已有一部分就只补最近的净值（`lsjz`），拉到已知日期就停。

### 净值日期固定按 UTC+8 折算（日历图「周五空着、周日有收益」的根因）

`pingzhongdata` 的 `Data_netWorthTrend[].x` 是**净值日 00:00（UTC+8）**的毫秒时间戳
（实测 `1789056000000` = 2026-09-11 的净值 1.7637、`1789401600000` = 2026-09-15 的 1.7209）。
早先的写法是 `DateTime.fromMillisecondsSinceEpoch(ts)`，即**按设备本地时区**解释：
手机时区只要在 UTC+8 以西（出国把时区改成 UTC+0 就会），整条序列的日期就全部提前一天。

后果全部落在净值日期上（交易日期是本机录入的，不受影响）：

- 日历图：**每周五空着、周日反倒有收益**（真周五的净值记到了周四，周四的记到了周三……整周左移一天）
- 周一那格常常显示 0：当日行情快照（`Quote.infoDate` 是接口给的字符串，日期正确）
  和「左移一天的真实净值」价格相同，相减正好是 0
- 后续的区间收益、3/5 年窗口、趋势图、资金流的日期都跟着偏

现在统一走 `cnDayFromEpochMillis()`（`core/format.dart`）**写死 UTC+8**，
行情接口的 `f86` 时间戳同理。已经写坏的旧数据不会自己变好——增量更新只补新日期——
所以「设置 → 数据维护中心 → **重建历史净值**」会先清掉本地净值再全量重抓一遍
（`AppState.rebuildNavHistory()`，只处理持仓 + 关注 + 基准指数）。

顺带修掉的另一个口径问题：某只标的在**某天没有新净值**时（周末、QDII 滞后、停牌），
逐日引擎原来会把它**上一次的涨跌再算一遍** —— 只要持有两只净值日不同的标的，
就会出现凭空的「周日收益」，日收益之和也不再等于累计收益的变化。现在只有当天
真的吃到新净值才计当日盈亏（`buildDailySeries`），并有用例钉住「日收益之和 =
区间内累计收益的变化」这个恒等式。

## 收益统计卡片（首页最底部）

三个页签：`日历图｜趋势图｜资金流`。页签、日历粒度与所选区间都放在 `AppState` 里
而不是组件内部——首页是 `ListView`，滚出屏幕的子节点会被卸载，放在组件里
翻一下就回到默认页签了。

### 日历图

`日收益 / 月收益 / 年收益` 分段控件切换的是**日历粒度**，不是三个并排的 KPI：

| 粒度 | 网格 | 该行的「累计收益」统计范围 |
| --- | --- | --- |
| 日收益 | 当月日历（周日起始），每格 = 日期号 + 当日盈亏 | **该月**合计 |
| 月收益 | 该年 12 格（`1月`…`12月`） | **该年**合计 |
| 年收益 | 按年的格子 | **建仓以来**合计 |

**`累计收益` = 当前视图所有格子之和**，即「这一段赚了多少」，不是账户级累计收益。
所以它随粒度与翻页变化，而且在屏幕上可以**逐个格子相加验算**；为负时按跌色显示。
整屏都没有净值数据时显示 `--`（不是 `¥0.00`，两者含义不同）。

- `‹ 2026 年 9 月 ›` 可翻页（两侧是圆角方形灰底按钮）；点标题弹年月快选（与日期选择器**共用同一个面板**）
- 格内金额**盈利红、亏损绿**（与全 App 一致），有盈亏的日子带一层**很浅的同色底**构成热力图，
  没有数据的日子只显示日期号、无底色；底部有 `● 盈利 ● 亏损` 图例
- 每天盈亏用**当日收盘份额**，与首页「今日收益」同口径；周末/停牌前向填充后差值为 0

### 趋势图

区间筹码 `当月 / 近3月 / 近6月 / 今年 / 全部 / 更多`（更多里是 近1年/近3年/近5年/自定义区间），
所有筹码共用一个灰色容器、选中项是白底蓝字胶囊。

纵轴是**区间累计收益率**（起点归零）：**红色实线**为本组合（带面积渐变）、**蓝色虚线**为参考基准；
按住/拖动出现**图内深色浮层** `收益 +x.xx％` / `差值 +x.xx％`，并带竖虚线指示与基准线上的蓝点；
底部左对齐显示 `阶段收益`。

**参考基准可切换**（点 `参考收益率` 那个灰框）：

| 类型 | 口径 |
| --- | --- |
| 自定义年化收益率 | 单利摊算 `年化 × 区间天数 ÷ 365`，默认 3.00% |
| 大盘指数 | 真实指数收盘价 `close(末)/close(起) − 1`，复用 `MarketIndex.presets`，沪深300 默认 |

- 指数历史走新浪日K，**上限约 6 年**（实测 `datalen=1500` 可用、`2000` 返回空）。
  区间比它更早时，两条曲线都从对齐起点开始，才是同区间可比
- 取不到基准值的点**留空断线**，不编造 0；基准完全没数据时图例显示「无数据」

### 资金流（直线思维导图）

区间筹码 `月 / 年 / 全部 / 更多`。展示所选区间的**各项总量**，不是流水明细：

```
期初资产   持仓市值 + 现金余额
投入金额   期间买入含手续费
赎回金额   期间卖出净额
净流入     充值 − 提现（为负时自动改叫「净流出」）
账户盈亏   期末 − 期初 − 净流入
现金分红   单独显示在期末资产正上方，标注「已计入期末资产」
期末资产   持仓市值 + 现金余额（含现金分红）
```

每个节点下方都写出**这个数是怎么来的**（算式），所以一眼看到的是总量与来源。

**两条独立恒等式**（回归测试同时锁死，任一口径写错都会被抓出来）：

```
① 期末资产 = 期初资产 + 净流入 + 账户盈亏            （账户盈亏取残差）
② 账户盈亏 = Δ持仓市值 − 投入金额 + 赎回金额
             + 现金分红 + 现金生息 + 现金调整
```

现金余额直接取现金账本（`Σ cash_txns.amount`），它已经含了分红与卖出回款
（两者由 `saveTxnWithCash` 联动写入），所以①按构造成立；②是用交易与现金流水
**另外算一遍**做交叉校验。数据正常时两式给出同一个数（多组区间均有测试覆盖）。

> **现金流水不完整时**（早年只补录了交易、没有配套现金流水），①仍然成立，但那笔
> 买入的钱没被记成支出、会被算进账户盈亏，于是它会明显大于首页的累计收益。
> 卡片会**显式提示**差额，并指向「现金管理 → 补记充值或调整」，
> 而不是静默给出一个看着像 bug 的数。

### 与首页的口径统一

收益统计卡片的历史序列，**最后一个有价日用行情快照覆盖**：基金的 `Quote.price`
可能是盘中估值，而 `nav_history` 存的是已公布净值，两者混用会让同一屏出现两个
对不上的「累计收益」。统一之后，卡片里的 `累计收益`、`期末资产` 分别与首页首卡的
`累计收益`、`总市值` 严格相等（已在设备上逐项核对）。

## 备份与恢复

**自动备份**：每天首次启动时，若已有交易记录，会自动在导出目录写一份
`自动备份_YYYYMMDD.json`，只保留最近 7 份。无需任何操作。

**手动导出 / 恢复**：设置 → 数据备份 → 导出完整备份 / 从备份恢复。

备份为单个 JSON，包含**账户、标的与分类、全部交易流水、现金流水、再平衡目标、设置**，
并保持它们之间的 id 引用关系（含 `cash_txns.src_txn_id` 指回交易）。
恢复是**整体覆盖**（单事务，失败自动回滚），界面上会先显示备份的时间与条数并要求二次确认。

> **版本 v2 起备份包含现金流水**。少了它，恢复后交易回来了、现金账本却是空的，
> 余额与交易对不上。v1 的老备份仍可解码，只是现金部分为空；恢复时会先清空
> `cash_txns` 再写入，避免旧流水与恢复后的交易错位。

行情缓存（quotes）刻意不进备份——它是可随时重新抓取的临期数据。

```bash

# 把备份放回去以便恢复
adb push 完整备份_20260914_003400.json \
  /sdcard/Android/data/com.dsh.invest_tracker/files/import/
```

## CSV 导入导出

导出使用 UTF-8 BOM + CRLF，Excel 打开中文不乱码。表头：

```
账户,标的类型,代码,名称,交易类型,日期,份额,价格,金额,手续费,备注
```

- `标的类型`：场外基金 / ETF/LOF / 股票 / 其他（也接受 fund/etf/stock/other）
- `交易类型`：买入 / 卖出 / 分红（也接受 buy/sell/dividend）
- `日期`：`2026-01-05`、`2026/01/05`、`20260105` 均可
- `金额` 留空时按 `份额 × 价格` 自动推算
- 导入时会自动创建缺失的账户与标的；无法解析的行会被跳过并在结果里逐条说明

文件目录（adb 收发）：

```bash
# 导入：把 CSV 放进 import 目录后在 App 里点「从 CSV 导入」
adb push 我的流水.csv /sdcard/Android/data/com.dsh.invest_tracker/files/import/

# 导出：在 App 里导出后拉回电脑
adb pull /sdcard/Android/data/com.dsh.invest_tracker/files/export/ .
```

## 依赖

`provider`（状态）、`sqflite`（本地存储）、`http`（行情）、`intl`（格式化）、
`path` / `path_provider`（路径）、`pinyin`（股票名生成首拼，约 +11 MB APK 体积）。
图表为自绘 `CustomPainter`，未引入第三方图表库。

> 若不想要这 11 MB，可以把 `pinyin` 降为构建期工具：用脚本预生成股票首拼种子打进
> assets，运行时不再生成。代价是新上市的股票没有首拼，只能靠联网兜底。

## 已知限制

- 支持多账户，但再平衡按「资产大类」而非按账户分别计算；持仓分布图也不含现金
- 关注列表的历史净值需要联网更新：**库里没有就全量拉，只有一部分就只补最近的净值**
- 现金的联动流水**不会为已存在的历史交易回补**（只有保存/编辑交易时才会写）
- 「拍照导入」的期初持仓不联动现金
- 调仓的关联 ETF 是**按名字猜的**（基础数据库里没有场内 ETF，靠联网搜索）：猜不到就留空、
  当日预估涨幅按 0 算，卡片上可以手动指定；猜错也能改
- 场外基金没有实时行情，只能用关联 ETF 估；ETF 自己的行情依赖行情接口，接口挂了就退回最新净值
- 记一笔表单里的净值查询：基金走 `f10/lsjz`，股票走 `push2his` 日 K（被限流时用新浪日K再兜一次），
  两条路都失败就只能手填——提示行会写明「联网查询失败，可手工填写净值」
- release 包使用 Flutter 模板自带的 debug 签名，正式分发前需替换为自己的签名
